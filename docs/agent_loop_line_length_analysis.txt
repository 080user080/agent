AgentLoop: аналіз проблеми "обмеження довжини рядка"
====================================================

Дата: 2026-05-14

Висновок
--------
Проблема не в реальному ліміті довжини рядка Python. Python може виконувати
дуже довгі рядки, якщо лапки та екранування сформовані правильно.

Реальний ланцюжок збою такий:

1. AgentLoop просить LLM повернути одну наступну дію.
2. LLM для створення або виправлення файлу вибирає execute_python замість
   write_file.
3. В аргумент execute_python.code потрапляє Python-код, а всередині нього є ще
   один багаторядковий рядок із вмістом цільового файлу.
4. Виникає вкладеність:
   JSON-рядок -> Python-код -> рядок із кодом цільового Python-файлу.
5. Якщо відповідь моделі обрізалась, містить зайву лапку або некоректне
   екранування, у пісочницю потрапляє вже зламаний скрипт. У логу видно саме:

   SyntaxError: unterminated string literal

6. Після цього агент трактує ситуацію як "main.py треба ще раз виправити" і
   починає знову генерувати execute_python-обгортку для перезапису main.py.

Друга важлива причина циклу
---------------------------
У AgentLoopConfig.expected_files були застарілі очікувані файли:

- statistics_tab.py
- run.py

А фактичне тестове завдання створювало:

- stats_tab.py
- main.py

Через це AgentLoop міг вважати проєкт незавершеним навіть після створення
потрібних файлів.

Що виправлено
-------------
1. Оновлено AgentLoopConfig.expected_files під поточне PyQt6-тестове завдання:

- constants.py
- base_tab.py
- chat_tab.py
- settings_tab.py
- logs_tab.py
- stats_tab.py
- about_tab.py
- tools_tab.py
- main.py

2. Додано runtime-захист у AgentLoop:

- виявляє, коли execute_python використовується для запису файлу через
  open(..., "w") або Path(...).write_text(...)
- запам'ятовує файли, які вже записувались через execute_python
- пропускає повторний execute_python для того самого файлу й підказує агенту
  перейти на write_file або done

Конкретна рекомендація
----------------------
Для задач генерації файлів агент має використовувати write_file або
детермінований code pipeline. execute_python варто залишити для перевірки,
невеликих обчислень і аналізу файлової системи, але не для запису великих
source-файлів через вкладені багаторядкові рядки.
