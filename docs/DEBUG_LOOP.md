# Debug-Loop — Універсальний алгоритм відладки

## Опис

Debug-Loop — це універсальний метод відладки, який використовується в цьому проекті для систематичного пошуку та виправлення помилок.

## Коли використовувати

Коли ви пишете в чаті слово **"дебаг"**, **"debug"**, або **"Debug-Loop"**, це означає що треба виконати саме цей метод.

## Універсальний алгоритм Debug-Loop

### Етап 1: Підготовка інструментарію (Логування)

Кожна функція, яку ми тестуємо, повинна стати "прозорою".

**Дія:** Додай запис у файл для кожної ключової події всередині функції.

**Що фіксуємо:**
- Які дані прийшли на вхід
- Який результат видала кожна внутрішня змінна
- Повний текст помилки (якщо вона є)

**Мета:** Не гадати, що пішло не так, а бачити це у файлі debug.log.

**Приклад логування:**
```python
def my_function(data):
    # Debug-Loop: Логування вхідних даних
    print(f"[DEBUG-MYFUNC] Вхід: data='{data[:50]}...' (len={len(data)})")
    
    try:
        result = process(data)
        # Debug-Loop: Логування проміжних результатів
        print(f"[DEBUG-MYFUNC] Проміжний результат: '{result[:50]}...'")
        return result
    except Exception as e:
        # Debug-Loop: Логування помилок
        print(f"[DEBUG-MYFUNC] Помилка: {e}")
        import traceback
        traceback.print_exc()
        raise
```

### Етап 2: Створення тестового сценарію

Замість ручного запуску коду використовуємо структуру твого успішного тесту (наприклад, test_aaa_osnova2).

**Дія:** Створи тест, який імітує реальну роботу функції.

**Структура тесту:**
1. **Arrange:** Підготуй вхідні дані
2. **Act:** Виклич функцію, яку ми "обгорнули" логами
3. **Assert:** Перевір, чи те, що повернула функція, збігається з твоїм очікуванням

**Приклад тесту:**
```python
def test_my_function():
    # Arrange
    test_data = "test input"
    
    # Act
    result = my_function(test_data)
    
    # Assert
    assert result == "expected output"
```

### Етап 3: Ітераційний цикл (The Loop)

Це повторюваний процес до моменту, поки код не стане ідеальним:

1. **Запуск:** Запускаєш тест
2. **Аналіз:** Якщо тест впав — відкриваєш лог-файл. Шукаєш останній запис і дивишся, на якому етапі дані стали некоректними
3. **Правка:** Виправляєш лише ту ділянку коду, яку "підсвітили" логи
4. **Повтор:** Знову запускаєш тест

## Приклад використання

### Проблема: Ctrl+F9 вставляє попередній буфер обміну

**Етап 1: Логування**
```python
def _start_recording(self):
    # Debug-Loop: Логування стану буфера перед очищенням
    old_clipboard = pyperclip.paste()
    print(f"[DEBUG-GVI] Буфер ПЕРЕД очищенням: '{old_clipboard[:100]}...' (len={len(old_clipboard)})")
    
    for i in range(3):
        pyperclip.copy("")
        current = pyperclip.paste()
        print(f"[DEBUG-GVI] Спроба {i+1} очищення: '{current}' (len={len(current)})")
        if not current:
            break
```

**Етап 2: Тестовий сценарій**
Створити тест який імітує натискання Ctrl+F9 і перевіряє чи буфер очищується правильно.

**Етап 3: Ітераційний цикл**
1. Запуск тесту
2. Аналіз логів - бачимо що буфер не очищується правильно
3. Правка коду - змінюємо метод очищення
4. Повтор тесту

## Переваги Debug-Loop

- **Систематичність:** Чіткий алгоритм дій
- **Прозорість:** Логи показують що саме відбувається
- **Ефективність:** Менше часу на гадання, більше на виправлення
- **Відтворюваність:** Тест можна запустити багато разів

## Правила Debug-Loop

1. Завжди додавай логування перед виправленням коду
2. Логи мають показувати вхідні дані, проміжні результати та помилки
3. Тест має бути простим і відтворювати реальну проблему
4. Виправляй тільки те, що показують логи
5. Повторюй цикл поки тест не пройде успішно
